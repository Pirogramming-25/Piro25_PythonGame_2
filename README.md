### game_4 : (장희원)

**게임 소개**

> 모든 플레이어는 1~99까지의 숫자 중 하나를 무작위로 배정받고 각자 배정받은 숫자의 십의 자리와 일의 자리를 비교하여 벌칙자를 선정합니다.

**벌칙 조건**

> Rule 1. 십의 자리가 겹칠 때 (최우선 적용) : 플레이어들 간에 십의 자리 숫자가 같은 경우가 발생하면, 그중 가장 작은 전체 숫자를 입력한 플레이어가 벌칙 당첨자가 됩니다.
> Rule 2. 일의 자리가 겹칠 때 (십의 자리가 모두 다를 때만 적용) : 모든 플레이어의 십의 자리 숫자가 전부 다르고, 일의 자리 숫자만 겹치는 경우가 발생하면, 그중 가장 큰 전체 숫자를 입력한 플레이어가 벌칙 당첨자가 됩니다.
> Rule 3. 게임 종료 : 모든 플레이어의 숫자가 십의 자리도, 일의 자리도 전혀 겹치지 않는다면 아무도 마시지 않고 게임이 종료됩니다.
> 추가 조건 1. 연속된 숫자 (11, 22, 33, 44, 55, 66, 77, 88) : 걸린 사람의 숫자가 이 중 하나라면, 해당 숫자를 가진 모든 플레이어가 연대책임으로 벌칙 1잔씩을 추가로 마십니다.
> 추가 조건 2. 0,9 : 걸린 사람의 숫자에 0 또는 9가 포함되어 있다면 (예: 9, 20, 49, 90 등), 해당 벌칙자만 1잔을 추가해서 마십니다.

### game_5 : (정현민)

**게임 소개**

> 서울 지하철 1~9호선에서 플레이어와 NPC가 돌아가며 현재 호선의 역 이름을 대는 콘솔 서바이벌 게임입니다.
> 시작할 호선을 외치면 순서대로 그 호선의 역을 하나씩 대고, 환승역에서는 역이름 환승 형식으로 다른 호선으로 갈아탈 수 있습니다. (그 역이 실제로 지나는 호선으로만 이동 가능)
> 서울 내의 지하철역으로만 범위를 한정하며, 수인분당, 경의중앙 등의 호선은 포함하지 않습니다.
> "이수 or 총신대입구"역은 "이수역"으로 통일합니다

**벌칙 조건**

> 아래 중 하나라도 해당하면 즉시 탈락하며, 탈락한 사람이 술을 마십니다.
>
> - 현재 호선에 없는 역을 댄 경우
> - 이미 나온 역을 다시 댄 경우 (중복)
> - 환승역이 아닌 곳에서 환승을 시도한 경우

## 🎮 게임 함수 계약 (가장 중요!)

각 게임은 **함수 하나로 캡슐화**

```python
# games/game_N.py
def play(current_player, others):
    # 이 안에서는 변수 이름 자유롭게 사용 가능 (모듈이 분리돼 있어 충돌 없음)
    ...
    return {current_player: 1}
```

**계약 3줄 요약**

1. 함수는 무조건 `def 함수이름(current_player, others):` — 이름 두 개, 순서 고정
2. `current_player`는 문자열, `others`는 문자열 리스트
3. 리턴은 무조건 `{이름: 잔수}` 딕셔너리, 아무도 안 마시면 빈 딕셔너리 `{}`

> 게임 종류가 자유롭고 여러 명이 마실 수 있어서 리턴을 딕셔너리로 통일
> 혼자 하는 게임은 `others`를 무시하면 되고, 대결형은 `random.choice(others)`로 상대를 고르기 때문에
> 파라미터를 다 안 써도 이상X

## 📁 폴더 구조

```
Piro23_PythonGame_O/
├── main.py              # 메인 실행 (이름/주량/초대/게임 리스트/게임오버 처리)
├── players.py           # 플레이어 상태 관리 (이름, 주량, 마신 잔 수)
└── games/
    ├── __init__.py      # 빈 파일 (games를 패키지로 인식시킴)
    ├── game_1.py        # 강보민
    ├── game_2.py        # 이지연
    ├── game_3.py        # 이주헌
    ├── game_4.py        # 장희원
    └── game_5.py        # 정현민
```

- 각자 **자기 `game_N.py` 파일 하나만** 작업 → 파일이 분리돼 있어 Git 충돌 거의 없음
- 실행은 반드시 최상위 폴더에서: `python main.py` (games/ 안에서 실행하면 import 실패)

## 🌿 브랜치 전략

- `main` : 최종 완성본 (직접 커밋 금지)
- `develop` : 개발 브랜치 (작업내용은 여기에 PR 날리기)
- `이름` : 각자 작업 브랜치 (예: `보민`, `지연`, `주헌`, `희원`, `현민`)
- 작업 시작 전 항상 `git pull origin develop`
- 작업 완료 → PR 올리기 → 리뷰 후 머지
